# 16 · 系统架构 v3 —— 独立前后端 + DSH 大脑

> 决策：**DSH 不再承担前端与服务**，只做「中间算法 + 对话交流」；整个系统为独立前后端产品。
> 插件模式（probe-1）保留为**开发原型/算法验证**，普通用户使用的是独立 Web 产品。

---

## 1. 架构总览

```
┌────────────────────────── 普通用户 ──────────────────────────┐
│  独立前端 Web（浏览器打开即用，无需 DSH/GUI/插件概念）         │
│  拓扑图 · 质量看板 · 健康评分 · 体检报告 · 对话建议(入口)      │
└──────────────────────────┬──────────────────────────────────┘
                           │ REST API（localhost:3210 / Tailscale）
┌──────────────────────────▼──────────────────────────────────┐
│  独立后端 probe/server（Node.js，无框架依赖）                  │
│  · HTTP API：/api/devices /api/topology /api/quality /api/… │
│  · 定时调度：5 分钟巡检 patrol（node timer）                   │
│  · 持久化：probe/data/*.json（覆盖/手册/账号/测量历史）         │
│  · 采集原语：child_process（arp/ping/netsh/node -e）          │
└──────────────┬─────────────────────────────┬────────────────┘
               │ 调用同一套引擎                 │
┌──────────────▼──────────────┐   ┌──────────▼──────────────────┐
│  探针引擎 engines/*（纯 Node）│   │  DSH 探针值守 Agent（大脑）   │
│  discovery/sweep/snmp/cctv/ │   │  · 自然语言对话/分析/决策      │
│  topology/rules/report/     │   │  · 驱动后端 API 或直接跑引擎   │
│  quality/knowledge          │   │  · 面向运维人员（创始人/技术）  │
└─────────────────────────────┘   └─────────────────────────────┘
```

**职责划分（明确边界）：**
| 层 | 组件 | 职责 | 用户 |
| --- | --- | --- | --- |
| 前端 | `probe/web/`（静态 HTML/JS，无构建） | 拓扑图/质量/报告可视化 | 普通用户（仓库老板/值班员） |
| 后端 | `probe/server/server.js`（Node API） | 数据、调度、持久化、采集原语 | —（本机服务） |
| 算法 | `probe/engines/*`（纯 Node 模块） | 全部算法：发现/质量/拓扑/评分/报告 | —（共享内核） |
| 大脑 | DSH 探针值守 Agent（preset `probe`） | 对话交流、分析解读、调整建议、指挥后端 | 运维人员（创始人/技术） |

## 2. 为什么这样分

1. **普通用户不接触 DSH**：插件/会话/GUI 对仓库老板是负担；独立 Web 打开即看。
2. **DSH 回归本质**：它是**语言与推理大脑**（算法已在 engines，DSH 负责「跑什么、怎么解读、怎么回答」），不是 Web 服务器。
3. **引擎一次开发多处复用**：engines 是纯 Node + 注入式原语（execPing/pingOnce），后端直接 require，DSH 插件曾内联的等价逻辑也由此收敛回唯一实现。
4. **部署友好**：后端 + 前端 = 一个 `node server/server.js`（Pi 上 systemd 托管）；DSH 大脑可跑在 Pi 或开发机（Tailscale 连后端 API）。

## 3. 数据流

```
探针(引擎) 扫描 → 后端持久化(data/*.json + measurements.json 历史)
    ├─ 前端轮询 REST：拓扑/质量/报告/资产
    └─ DSH 大脑：对话触发后端 POST /api/scan|quality，或直接跑引擎；
                  解读薄弱环节 → 建议；asset_update 覆盖落盘 → 前端图实时反映
```

## 4. 迁移对照（插件 → 独立系统）

| 插件（probe-1，原型） | 独立系统 | 说明 |
| --- | --- | --- |
| probe_ping / scan_subnet / port_scan | 后端 /api/scan、engines | 引擎复用 |
| link_quality | 后端 POST /api/quality + /api/quality | 历史进 measurements.json（稳定性趋势） |
| topology_build / topology_describe | 后端 /api/topology + 前端 SVG 图 | 前端图形化 |
| asset_update / assets_list | 后端 POST/GET /api/asset、/api/assets | 人工补充照旧 |
| health_report / diagnostic_report | 后端 /api/report/* | 报告照旧 |
| Client 大屏（DSH GUI） | 前端 Web（自绘 SVG） | 脱离 DSH |
| patrol 定时 | 后端 node timer | 脱离 DSH |

## 5. 安全与部署

- API 默认只监听 `127.0.0.1:3210`；跨设备访问经 Tailscale（出站，不暴露公网）。
- 账号记录输出脱敏（密码••••）；采集只读协议，零写入承诺不变。
- Pi 部署：`systemd` 托管后端（模板见 deploy/），前端静态文件同源提供；DSH 大脑可选。
