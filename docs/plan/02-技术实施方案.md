**两种运行模式：**
- **模式 A（现场演示/调试）：** 笔记本 Claude Code 通过 MCP 直连现场探针 —— 用于交付当天「AI 实时诊断演示」与疑难排查。

## 4. 网络发现引擎（多协议交叉验证，目标准确率 ≥90%）

### 4.1 三层扫描（设备清单）
| 协议 | 实现 | 用途 |
| --- | --- | --- |
| ARP 扫描 | `arp-scan` / 解析 `/proc/net/arp` | 局域网活跃 IP + MAC |
| mDNS | `avahi-browse -a` | 发现打印机/Apple/智能设备主机名 |
| ICMP | ping 扫描（低速，防触发 IPS） | 存活确认 |
| 端口探测 | `nmap -Pn -p 80,443,554,5060,8080 -T3`（限速） | 识别 Web/CCTV/网络设备类型 |
| MAC OUI | 本地 OUI 数据库（IEEE 官方 csv 每月更新） | 品牌识别：Cisco/Hikvision/Ubiquiti… |

### 4.2 二层拓扑（链路关系）
| 数据源 | MIB / 方式 | 说明 |
| --- | --- | --- |
| LLDP | `1.0.8802.1.1.2`（LLDP-MIB，lldpRemTable） | 端口级物理连接，首选 |
| 交换机 CAM 表 | BRIDGE-MIB `dot1dTpFdbTable` | MAC→端口映射，定位设备挂载端口 |
| 网关 ARP 表 | SNMP IP-MIB `ipNetToMediaTable` | 跨网段设备定位 |
| 设备挂载 | 三者交叉比对 | 生成「交换机端口 → 设备」精确拓扑 |

### 4.3 防火墙/广播阻断时的降级路径（自动切换）
```
SNMP 只读可用？ ──是──► LLDP + CAM 交叉验证（首选，准确率最高）
        │否
        ▼
被动监听：tcpdump 混杂模式抓源 MAC/IP（5 分钟窗口）
        │
        ▼
低速单播探测：nmap -Pn 限速扫 554/80/443（避开 IPS 特征）
        │
        ▼
降级输出：标注「推测拓扑（被动监听）」+ 置信度，报告如实说明
```
> 原则：**宁要诚实的低置信度，不要编造的 100%。** 报告必须标注每条连接的数据来源与置信度。

## 5. CCTV 诊断引擎

| 能力 | 实现 | 输出 |
| --- | --- | --- |
| 摄像头发现 | RTSP 554 端口扫描 + ONVIF Device Discovery（WS-Discovery） | 摄像头清单 |
| 码流健康 | ONVIF GetStreamUri → `ffprobe` 探测分辨率/编码/帧率/码率 | 在线/离线/分辨率异常 |
| 黑屏/画面异常 | 定时拉 1 帧（`ffmpeg -frames:v 1`）→ 像素方差/灰度统计 | 黑屏、花屏、静态画面（疑似冻结） |
| 录像状态（可选） | 客户提供 NVR 只读账号 → ONVIF/HTTP API 查录制状态 | 断录告警 |
| 断流诊断 | 连续 3 次探测失败 → 判定离线，自动尝试 5 分钟后再探（区分断电/断网/摄像头死机） | 事件 + 建议动作 |

> 合规红线：**只探测码流元数据与单帧画面用于黑屏判断，不录制、不存储、不导出客户监控内容**。单帧仅内存比对后丢弃。若客户明确同意，可将黑屏截图放入本地报告（默认关闭）。

## 6. 自愈执行器（Permission-Gated，默认关闭）

| 动作 | 触发条件 | 技术实现 | 前置授权 |
| --- | --- | --- | --- |
| PoE 端口重启 | 摄像头/AP 连续 3 分钟无响应 | SNMP v2c/v3 `ifAdminStatus` down→up，间隔 10s | 客户签署《自愈授权书》 |
| 交换机端口隔离 | 检测到风暴/环路 | SNMP 关闭异常端口并告警 | 同上 + 白名单 |
| AP 远程重启 | AP 掉线且 PoE 重启无效 | SSH（客户提供凭据）或云 API（UniFi/Meraki） | 同上 |
| 路由/防火墙重启 | **不做**（风险过高） | — | — |

**安全设计：**
- 默认只读运行 30 天，客户体验稳定后才开启自愈。
- 凭据用 `age` 加密存储，仅现场解密；记录每次写操作到 `audit.log`。
- 每次自愈动作前自动快照端口状态，可一键回滚。
- 单日单端口自愈上限 3 次，超出转人工工单（防止「抖动」误伤）。

## 7. MCP 工具集（Python FastMCP Server，接口规格）

| 工具 | 输入 | 输出 | 说明 |
| --- | --- | --- | --- |
| `arp_discovery` | `subnet?` | 设备清单[{ip,mac,oui_vendor,hostname,first_seen,last_seen}] | 快速局域网资产摸盘 |
| `snmp_query_switch` | `host, community?, auth?` | 端口表[{port,status,ifName,speed,in_err_ratio,poe_power}] | 交换机端口流量/PoE/错误包 |
| `inspect_rtsp_cctv` | `rtsp_url? / scan_mode` | 摄像头健康[{id,ip,status,resolution,fps,bitrate,anomaly}] | 探测 554 与码流状态 |
| `topology_build` | `--` | 拓扑图 JSON（节点+链路+置信度） | 交叉验证结果 |
| `health_report` | `--` | Markdown《IT/安防健康诊断报告》 | 汇总发现+评分+建议 |
| `self_heal` | `action, target, port?` | 执行结果 + 回滚信息 | **仅授权后可用** |
| `local_ai_analyze` | `text` | 隐患分析与建议（Ollama 本地模型） | 数据不出现场 |

**开发约定：**
- 所有工具幂等、只读优先；写操作（self_heal）必须有 `AUTH_TOKEN` 二次校验。
- 错误返回结构化 `{ok:false, reason}`，禁止裸抛异常到 MCP 层。
- 每个工具 ≤10s 超时；批量探测使用异步并发 + 速率限制（默认 50pps）。
- 验收：模式 A 演示 10 分钟跑通「发现→拓扑→CCTV 诊断→报告」全链路。

## 8. 数据与隐私合规设计（信任承诺的工程实现）

| 承诺 | 工程实现 |
| --- | --- |
| 零安装、零写入 | 探针仅出站协议，不装客户 Agent；采集默认只读 |
| 不碰业务数据 | 抓包仅解析 L2/L3 头（源/目的 MAC、IP、协议号），**不解析应用层载荷** |
| 数据最小化 | 仅存：设备 MAC/IP/端口/型号/健康状态/事件时间；**不存监控画面、不存流量内容** |
| 本地优先 | 数据默认存探针本地 SQLite，保留 30 天滚动清理；看板/日报/报告全部本地生成 |
| 云上传（可选） | 仅在客户书面同意后开启；只上传**聚合健康评分与告警事件**（无设备级明细，可配置脱敏） |
| 删除权 | 拔线即停止采集；客户可随时要求清除本地数据（一键 wipe）并出具清除证明 |
| 合规依据 | 德州 TDPSA（2024-07-01 生效）适用性评估见 08 文档；B2B 网络元数据一般不构成个人数据，但 CCTV 单帧画面需按个人数据对待 |
