# 13 · 探针开发任务清单（DSH 自研版）

> 执行人：**DSH agent（自研，无外包）**。本文取代 12 文档 §6 的「外包口径」，是探针从 0 到 1 的**唯一开发依据**：里程碑、任务、验收标准、用到的 DSH 平台能力、本机可测性。

---

## 0. 开发方针（先读）

1. **双阶段开发**：先在本机（Windows + DSH 运行时）用等价命令验证全部逻辑 → 再出 Pi（Linux）部署版。跨平台逻辑不变，只换 CLI。
2. **实现载体**：cordis 动态插件（当前会话 PoC）→ 最终落为**探针 preset**（生产，`~/.dsh/.agent-presets/probe/`）。
3. **内核全借、外壳自研**：协议内核调 CLI（arp-scan/nmap/net-snmp/ffprobe），DSH 侧全部是薄壳（参数/授权/审计/输出）。
4. **平台约束（实测确认）**：Host 插件**无 `require`/`import`/`process`/`Buffer`** → 进程用 `subprocess` Service、定时用 `timer` Service、持久化用 `storageDomain`/`fs`（JSON）、HTTP 用 `webServer`、凭据用 `credentials`、LLM 用 `llm`。
5. **本机等价命令**：`arp -a`、`ping`、`Test-NetConnection -Port`、`netsh wlan show interfaces` —— 本次摸盘已全链路实证。

## 2. 详细任务清单

### M0 · 项目骨架 + cordis 插件壳（P0，0.5 天）

**任务**
- 建立仓库结构：`probe/`（`plugins/host`、`plugins/client`、`engines/`、`data/`、`deploy/`、`docs/`）
- cordis 插件（Host 半）：`harness.defineTool` 注册首个探针工具 `probe_ping`；`timer.interval` 骨架；`console` 日志
- cordis 插件（Client 半）：注册一个占位 Slot（验证 Client 通路）
- 探针 preset 骨架（cordis.yml 结构，先空壳后填）

**验收**
- [ ] 插件运行后 `probe_ping <ip>` 工具可被 agent 调用并返回 JSON
- [ ] Client 占位 Slot 出现在 DSH Web GUI
- [ ] 停止/更新插件无残留（ctx.effect 全部可回收）

**DSH 能力**：`harness.defineTool/registerTool`、`ctx.effect`、`ctx.get('timer')`、`cordis_define/cordis_run`

### M1 · 数据层（P0，0.5 天）

**任务**
- 数据模型（JSON，`storageDomain` 或 `fs` 落盘到 `probe/data/`）：
  - `devices.json`：`{ip, mac, oui, vendor, type, ports[], firstSeen, lastSeen, status, confidence}`
  - `events.json`：`{ts, level(P1–P4), kind, target, detail, autoHealed}`
  - `config.json`：`{site, snmpCommunity?, credentialsRef, selfHealEnabled, notifyEmail}`
  - `audit.log`：所有写操作留痕（自愈/凭据访问）
- CRUD 工具函数（load/save/upsertDevice/appendEvent）

**验收**
- [ ] 资产增改、事件追加、配置读写单测通过（Node 直接跑）
- [ ] audit.log 每笔写操作有记录

**DSH 能力**：`ctx.get('fs')` / `ctx.get('storageDomain')`

### M2 · 发现引擎（P0，1.5 天）

**任务**
- ARP 摸盘：本机 `arp -a` 解析；Pi 版 `arp-scan --localnet`
- 存活探测：`ping`（本机 `Test-Connection -Count 1 -Quiet`）
- 端口探测（限速）：554/80/443/8080/22，Pi 版 `nmap -Pn -T3 -p 554,80,443,8080,22 --max-rate 50`
- OUI 厂商识别：`web.fetch` 查 maclookup.app（在线，带缓存）+ 本地 OUI csv（离线兜底）
- 随机 MAC 识别（本地管理位 0x02）→ 标注「隐私地址」
- 设备类型推断：554→摄像头；80/443+厂商→管理页；打印协议/厂商→打印机等（规则表）

**验收**
- [ ] **本机复刻摸盘**：对 10.0.0.0/24 输出 ≥28 台设备，厂商与 11 文档清单一致
- [ ] 一轮扫描 ≤60 秒；nmap 限速参数内置
- [ ] 随机 MAC 设备正确标注

**DSH 能力**：`subprocess.spawn`、`web.fetch`、`timer`

### M3 · SNMP 引擎（P0，1.5 天）

**任务**
- `snmpwalk`/`snmpget` 封装（Pi：net-snmp；本机：先封装命令，逻辑在 Pi 上实测）
- MIB 读取：LLDP-MIB `1.0.8802.1.1.2`（lldpRemTable）→ 端口级链路；BRIDGE-MIB `dot1dTpFdbTable` → MAC→端口；IF-MIB → 端口状态/错误包；IP-MIB `ipNetToMediaTable` → 网关 ARP；POWER-ETHERNET-MIB → PoE 状态/功耗
- 凭据：`credentials` 服务加密存储，社区串/SNMPv3 配置
- 无凭据/超时 → 优雅降级（返回空 + 标记「SNMP 不可用」）

**验收**
- [ ] 有凭据环境（自建 VM 交换机模拟或客户现场）读端口表/PoE/LLDP 成功
- [ ] 无凭据时流程不中断，报告如实标注
- [ ] 凭据不出现在日志/审计明文

**DSH 能力**：`subprocess.spawn`、`credentials`、`console`

### M4 · CCTV 引擎（P0，1 天）

**任务**
- 554 端口探测 + RTSP URL 构造（`rtsp://ip:554/...` 常见路径表）
- `ffprobe` 拉码流元数据：分辨率/编码/帧率/码率 → 在线/离线/异常
- 黑屏/静态帧：`ffmpeg -frames:v 1` 单帧 → 像素方差（内存处理，**不落盘不存储**）
- ONVIF（可选，P2）：python-onvif 做标准发现与配置查询

**验收**
- [ ] 本机网络：4 台摄像头（3 TP-Link + 1 海康）在线状态与码流识别正确
- [ ] 断流判定：连续 3 次失败 → 离线事件；5 分钟后自动复探
- [ ] 单帧仅内存比对后丢弃（无画面落盘）

**DSH 能力**：`subprocess.spawn`

### M5 · 拓扑构建（P0，1 天）

**任务**
- 三源交叉验证：LLDP（有）→ CAM 表 → 网关 ARP → 被动监听（预留 Zeek 接口）
- 图结构：`{nodes:[{id,ip,mac,type,vendor,health}], links:[{a,b,via,confidence}]}`
- 置信度规则：LLDP=高、CAM+ARP 交叉=高、单源=中、被动=低（如实标注）
- 降级链：SNMP 不可用 → ARP+端口探测 → 被动（tcpdump/Zeek）

**验收**
- [ ] 输出拓扑 JSON 与渲染数据（vis.js 可用格式）
- [ ] 每条链路带数据来源与置信度（报告如实原则）

**DSH 能力**：纯逻辑（Node 模块），`fs` 读写

### M6 · 巡检调度 + 自愈执行器（P0，1.5 天）

**任务**
- `timer.interval(300_000)` 5 分钟巡检：全资产存活+CCTV+SNMP 关键端口
- 规则引擎：掉线判定（连续 3 次）、P1–P4 分级、告警抑制（30 分钟同类去重）、维护窗口静默
- 自愈执行器（**默认只读 30 天**）：
  - PoE 重启：SNMP 写 `ifAdminStatus` down→up（10s 间隔）
  - 快照回滚：动作前记录端口状态，可一键恢复
  - 日上限 3 次/端口，超出转 P2 工单（防抖动）
  - 每次动作写 `audit.log`
- 授权门：`approval` 服务 + `credentials`（凭据）双重要求；未授权 → 只告警不动作

**验收**
- [ ] 模拟掉线（本机断网/停服务）→ 触发 → 自愈/升级人工路径正确
- [ ] 未授权状态下零写操作（只告警）
- [ ] 审计完整：时间/对象/动作/结果/回滚状态

**DSH 能力**：`timer.interval`、`approval`、`credentials`、`subprocess.spawn`

### M7 · 报告与通知（P0，1 天）

**任务**
- 健康评分模型：网络/安防/机房三块 0–100（在线率/自愈率/错误包/存储占用等加权）
- 日报模板（09 文档 §6 格式）→ 生成 Markdown → 邮件（SMTP：`msmtp`/`curl`，Pi）
- 14 天诊断报告：资产清单/拓扑/事件统计/隐患分级/升级建议 → Markdown → PDF（`pandoc`/`weasyprint`，Pi）
- AI 小贴士：`llm` 服务生成（可配置关闭；隐私客户切本地 Ollama）

**验收**
- [ ] 本机生成日报样例（10.0.0.0/24 真实数据）+ 报告 PDF
- [ ] 评分与 09 文档日报模板一致；PDF 中文可读

**DSH 能力**：`llm.stream`、`subprocess.spawn`、`fs`

### M8 · 大屏与本地 Web（P1，1.5 天）

**任务**
- Host：`webServer.register` 提供 `/api/status`、`/api/topology`、`/api/devices` JSON
- Client 插件（Slot）：拓扑图（vis.js）、健康分卡片、CCTV 在线矩阵、AI 小贴士滚动、事件流
- 演示模式（可模拟异常，用于现场 Demo）
- kiosk 适配（全屏无边框，HDMI 输出）

**验收**
- [ ] 本机浏览器打开 DSH Web GUI 看到探针看板，数据来自真实巡检
- [ ] 拔网线 → 看板在离线状态仍可渲染本地缓存数据（信任卖点）

**DSH 能力**：`webServer.register`、Client `Slots`、`harness.handle`（Client↔Host RPC）

### M9 · Pi 部署打包（P1，1 天）

**任务**
- 镜像：Raspberry Pi OS Lite（64-bit）+ Node 20 LTS + DSH headless
- 依赖安装脚本：`arp-scan net-snmp ffmpeg nmap msmtp pandoc (可选 zeek frigate)`
- systemd 单元：`dsh-probe.service`（自启/崩溃重启）+ 看板 kiosk（可选）
- 加固：ufw 只开放本地、Tailscale 出站、SSH Key、只读根（可选 overlayfs）、unattended-upgrades
- 探针 preset 落盘 + 首次启动初始化（站点配置向导）

**验收**
- [ ] Pi 上跑通：发现→拓扑→日报全链路
- [ ] 断电重启自恢复；拔线不残留（一键 wipe）

**DSH 能力**：无（部署工程），产物为 `deploy/` 脚本与文档

## 5. 依赖与风险

| 项 | 说明 |
| --- | --- |
| 依赖（Pi） | arp-scan、net-snmp、ffmpeg、nmap、msmtp、pandoc（可逐个按需安装） |
| 风险 1 | 本机无 SNMP 交换机 → M3 验收依赖自建 VM 交换机（`net-snmp` 模拟器）或客户现场 |
| 风险 2 | DSH Web GUI 在 Pi（ARM64）运行需验证 → M9 首日 spike，失败则大屏改用 Grafana kiosk |
| 风险 3 | Windows 无 LLDP CLI → M5 的 LLDP 分支逻辑先写、Pi 上实测 |
| 缓解 | 所有风险都只影响「验收时机」，不影响逻辑开发；Pi 到货前先完成全部本机可测部分 |
