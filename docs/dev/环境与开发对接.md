# 环境与开发对接

第 1 步的产物：一套能跑起来的基础设施、开发时前后端怎么接、提交后怎么构建。

---

## 1. 一键起环境

```powershell
cd buildingos.harenss\deploy
powershell -ExecutionPolicy Bypass -File setup.ps1
```

跑完会打印连接信息。重复执行安全（建表脚本都是 `IF NOT EXISTS`）。

Linux / 树莓派上没有 PowerShell，等价两步：

```bash
docker compose -f docker-compose.infra.yml up -d
docker exec netops-infra-tdengine-1 taos -f /init/tdengine.sql
```

**当前状态（已验证）**：PostgreSQL 建了 16 张业务表，TDengine 建了 `netops` 库和 `metric` 超表。

### 我们的服务

| 服务 | 宿主机端口 | 凭证 |
|---|---|---|
| PostgreSQL | `127.0.0.1:55432` | 库 `netops` / 用户 `netops` / 密码 `netops_dev_only` |
| TDengine（REST） | `127.0.0.1:56041` | 库 `netops` |
| TDengine（原生） | `127.0.0.1:56030` | |
| MQTT（可选） | `127.0.0.1:51883` / 面板 `58083` | 密码 `netops_dev_only` |
| **DSH（AI 引擎）** | **`127.0.0.1:3090`** | 访问地址带 token，见 `docker logs netops-infra-harness-1` |
| 探针服务 | `3210` | 已有实现 `apps/probe/server/server.js` |
| 后端 API | `8080` | 待建 |
| 前端 dev | `3890` | 待建 |
| 前端 preview | `4890` | 待建 |

### 端口为什么是这些怪数字

本机已经跑着**另一套 buildingos 共享基础设施**（`buildingos-postgres-1node` 占 5432、`buildingos-emqx-1node` 占 1883/18083、`buildingos-nodered-1node` 占 1880），而且 ioc 的 dev server 占着 3888。

那套是别的项目在用、凭据也不同。**我们不去碰它**，用错开的端口自建一套 —— 既避免冲突，也贴近产品形态（一体机自带一套）。

MQTT 默认**不启动**：单机部署时采集器直连数据库就够。要做「现场小盒子 + 公司集中库」的分离部署时再启用：

```bash
docker compose -f docker-compose.infra.yml --profile mqtt up -d
```

## 3. 开发时前后端怎么对接

**原则：后端跑容器，前端跑宿主机。** 前端要热更新，塞进容器每次改都要重建，太慢。

```
┌─ 宿主机 ────────────────────┐   ┌─ 容器 ──────────────┐
│  前端 dev server  :3890     │   │  postgres   :55432  │
│    └ /api 代理 ─────────────┼──▶│  tdengine   :56041  │
│  后端 API         :8080     │   │  mqtt(可选) :51883  │
└─────────────────────────────┘   └─────────────────────┘
```

前端 `vite.config.js` 里把 `/api` 代理到后端：

```js
server: {
  port: 3890,
  proxy: { '/api': 'http://127.0.0.1:8080' },
}
```

这样前端代码里直接写 `fetch('/api/devices')`，开发和生产都不用手改地址 —— 生产环境由 nginx 把 `/api` 反代到后端容器。

**日常开发的三条命令：**

```powershell
docker compose -f deploy/docker-compose.infra.yml up -d   # 起数据服务（一天一次就够）
cd apps/web ; pnpm dev                                    # 前端，热更新
cd apps/api ; pnpm dev                                    # 后端，热更新
```

**联调验收**：打开前端页面能看到真实数据库里的数据（不是 mock），且改后端代码不用重启前端。

## 4. 提交后怎么构建

`.github/workflows/build.yml`，推送到 `master`/`main` 或开 PR 时触发。

```
validate  ──▶  build
   │              │
   │              └─ 对 apps/ 下每个带 Dockerfile 的目录构建镜像推到 ghcr
   └─ 校验 infra 编排语法
      校验完整编排（若已建立）
      用真 postgres 跑一遍 packages/db/schema.sql，语法错立刻失败
      自动发现 apps/*/Dockerfile 并输出成构建矩阵
```

**两个刻意的设计：**

1. **`apps/` 下新加一个带 `Dockerfile` 的目录，CI 自动就构建它，不用改 workflow 文件。** 现在还没应用，矩阵是空的，构建任务自动跳过。
2. **建表脚本在 CI 里用真 PostgreSQL 跑一遍。** 不是文本检查，是真执行 —— 列名拼错、类型写错、外键引错，当场失败。

镜像标签：`ghcr.io/<org>/<repo>/<app>:<commit-sha>` 和 `:latest`。

**文档改动不触发构建**（`paths-ignore: docs/**, **/*.md`），改 md 不用等 CI。

## 6. 排错记录（这次踩的坑，省得再踩）

| 现象 | 原因 | 处理 |
|---|---|---|
| TDengine 建库脚本没执行 | 它的镜像**不认** `/docker-entrypoint-initdb.d`（那是 postgres 的约定） | `setup.ps1` 里用 `docker exec ... taos -f` 执行 |
| `Incomplete SQL statement` | `taos -f` 是**逐行执行**的，SQL 不能跨行 | `tdengine.sql` 里每条 SQL 写成一行 |
| `syntax error near "value double"` | **`VALUE` 是 TDengine 保留字**，不能当列名 | 列名改 `val`；对外 JSON 仍叫 `value`，后端做一次映射 |
| PowerShell 脚本中文乱码、语法报错 | PS 5.1 按 GBK 读无 BOM 的 `.ps1` | `.ps1` 存成 **UTF-8 with BOM** |
| `powershell -File` 明明跑成功却 exit 1 | 脚本内 `docker exec` 的退出码被当成脚本退出码 | 脚本末尾 `exit 0` |
| 广播/组播探测 0 响应 | 虚拟网卡的接口优先级高于真实网卡，包从错网卡出去了 | 探针必须显式声明出口网卡（`NETOPS_EGRESS_IFACE`） |

## 7. DSH（AI 引擎）容器

**它在产品里的位置**：AI 引擎是产品的大脑，不是一个可选附件。没有它，系统就只是一堆数据。

```powershell
docker compose -f deploy/docker-compose.infra.yml up -d harness
docker logs netops-infra-harness-1          # 日志里会打印带 token 的访问地址
```

容器里装了什么：

| 组件 | 说明 |
|---|---|
| DSH 本体 | `@deepseek-ai/dsh@0.1.5-rc.2`（npm 已发布） |
| profile | `netops`，首次启动自动初始化，之后每次启动用 `harness/profile/` 覆盖 |
| 网络工具 | ping / arp-scan / nmap / snmp / traceroute / python3（只读探索要用） |
| 模型凭据 | 开发期借用宿主机 `~/.dsh/.credentials.yaml`，用 600 权限装载 |
| 监听地址 | 在 profile 里把 `webserver` 行的 `host` 覆盖成 `0.0.0.0`（默认只绑 127.0.0.1） |

**profile 组合校验**：入口脚本每次启动都会跑 `dsh --profile netops --dump-config`，配置坏了一看就知道哪层出问题。当前是 **545 行**（少了 web-app 时只有 343 行）。

### 怎么拿到访问地址

```powershell
cd deploy
powershell -ExecutionPolicy Bypass -File url.ps1          # 打印地址
powershell -ExecutionPolicy Bypass -File url.ps1 -Open    # 打印并打开浏览器
```

或者直接看日志，启动横幅里就有：

```powershell
docker logs netops-infra-harness-1 | Select-String 'token='
```

### 关于 token 和 401

DSH 的访问 token 是进程内 `randomBytes()` 生成的、存在 WeakMap 里，**没有配置项能固定**，每次重启都换一个。

| 情况 | 结果 |
|---|---|
| 直接开 `http://127.0.0.1:3090/` | **401** `dsh web authentication required` |
| 用带 token 的完整地址打开 | 303 跳转 + 种 cookie（**有效期 30 天**） |
| 之后直接开 `http://127.0.0.1:3090/` | 200 正常 |

所以：**首次必须用带 token 的地址**，之后浏览器里存了 cookie 就不用再管了。换浏览器或清 cookie 后要重新来一次。

## 8. 排错记录（这次踩的坑，省得再踩）

### 数据库

| 现象 | 原因 | 处理 |
|---|---|---|
| TDengine 建库脚本没执行 | 它的镜像**不认** `/docker-entrypoint-initdb.d`（那是 postgres 的约定） | `setup.ps1` 里用 `docker exec ... taos -f` 执行 |
| `Incomplete SQL statement` | `taos -f` 是**逐行执行**的，SQL 不能跨行 | `tdengine.sql` 里每条 SQL 写成一行 |
| `syntax error near "value double"` | **`VALUE` 是 TDengine 保留字** | 列名改 `val`；对外 JSON 仍叫 `value`，后端做一次映射 |

### DSH 容器

| 现象 | 原因 | 处理 |
|---|---|---|
| 容器起来但**永不监听端口**，CPU 0%、内存 68MB 不动 | init 出来的 profile 的 `dsh.profile.bundles` **只有 `dsh-base`，没有 `dsh-web-app`**。`dsh plugin add` 只装包，不会往 bundles 列表里写。HTTP 服务那一行根本没被组合进来，进程启动完就在事件循环里干等 | 启动脚本用我们自己的 `package.json` 覆盖 profile 的（配置行数从 343 涨到 545） |
| `credentials-local: ... is readable beyond its owner (mode 777)` | DSH 拒绝读属主以外可读的凭据文件；Windows 挂进来的文件在容器里是 777 | 挂到 `/run/secrets`，入口脚本用 `install -m 600` 拷进 `$DSH_HOME` |
| `Cannot find package '@deepseek-ai/dsh-experimental-code-runtime-python'` | 这个 Python 代码运行时包**没发布到 npm**（404） | 先注释掉；PTC 走 JS，模型要跑 Python 就走 shell |
| Windows 浏览器连不上容器 | Docker Desktop 的 `network_mode: host` 绑的是 **WSL2 虚拟机的网卡**，不是 Windows | 默认改 bridge + 端口映射；Linux/树莓派上用 `docker-compose.host-net.yml` 覆盖成 host |
| 端口映射了却连不上 | DSH 默认只绑 **127.0.0.1**，docker 的端口映射连的是容器网卡地址，连不上回环地址。CLI 的 `--host 0.0.0.0` 会被明确拒绝（作者怕把远程代码执行暴露到网络），但 **webserver 本身是支持 `0.0.0.0` 的** | 在 profile 用户层覆盖 `webserver` 行的 `host: '0.0.0.0'`（注意 patch 会替换整块 config，每个键都要重述）。**不需要任何端口转发** |
| `dsh web authentication required` | 访问地址要带 token；token 里有下划线，我用 `[A-Za-z0-9]+` 提取时被截断了 | 用完整 token，会 303 跳转并种 cookie |
