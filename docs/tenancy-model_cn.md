# BuildingOS 租户模型与数据边界（DRAFT v0.1）

> 状态：DRAFT v0.1 —— 进入 M1 前的数据模型契约，是 §6 Adapter Contract 的 `compile()` 接口定义"**数据从哪来、往哪去**"的依据。
> 关联：[契约哲学](../契约哲学.md) D16–D18；[api-contract.md](api-contract.md) §2 核心概念、§4.6 工具治理；[schemas/](../schemas/README.md) 家族。

## 1. 核心原则

1. 【已定】**Git 仓库 = 应用的大脑 + 世界模型，不是用户数据。** 仓库装两类文档：行为文档（rules / skills / prompts / configs，怎么想怎么干）+ 世界知识文档（network.md 类，这个世界长什么样）；用户数据（会话状态、事务数据）不进仓库。
2. 【已定】**三层数据边界**：租户共享（Git）→ 用户会话私人状态（运行时状态库）→ 用户业务数据（既有系统，工具访问）。
3. 【已定】**隔离是构造性的**：租户级（仓库）、用户级（会话）、工具级（权限由规则派生）。
4. 【已定】**知识 vs 数据判据（D19）**：**值得人评审、会被人改、版本重要 → 进 Git（知识）；即时状态、高频、不值得评审 → 留 DB（数据）。**

## 2. 三层数据边界

| 层           | 内容                                                                          | 存储                     | 隔离                                    |
| ----------- | --------------------------------------------------------------------------- | ---------------------- | ------------------------------------- |
| **租户层**     | 应用源代码：rules / skills / prompts / configs + 共享业务数据（如拓扑文件，skill 的 `data:` 声明） | 租户 Git 仓库              | 租户间隔离（一客户一仓库）                         |
| **用户会话层**   | 对话历史、记忆、个人偏好                                                                | 运行时状态库（PG + 向量 + 知识图谱） | 按 user / session 隔离，**不进 Git 仓库**     |
| **用户业务数据层** | C 端用户自己的数据（订单 / 资料）或 B 端业务数据                                                | 既有业务系统                 | 经 MCP 工具 + 用户级授权访问，BuildingOS **不复制** |

### 2.1 知识 vs 数据（D19 判据）

| 类型              | 例子                    | 存放              |
| --------------- | --------------------- | --------------- |
| **知识**（关于世界的陈述） | network.md、拓扑、基线、操作规程 | ✅ Git（评审 / 版本化） |
| **状态**（世界的即时状态） | 对话历史、MIS 流水、临时记忆      | ❌ 状态库 / DB      |

判据：**"值得人评审吗？会被人改吗？版本重要吗？"** 是 → Git；否 → DB。

一次用户请求的数据流：

```
用户输入 → 会话（状态库读记忆/偏好）
        → 上下文构建（租户 Git：rules/skills/prompts + data: 声明）
        → 引擎执行（MCP 调用业务系统，凭用户级授权）
        → 结果写回会话状态库
```

## 3. 两种部署形态

| 形态      | 租户 =            | 用户 =            | 典型场景           |
| ------- | --------------- | --------------- | -------------- |
| **B 端** | 一个客户（一个 Git 仓库） | 客户员工（会话隔离）      | 企业 AI 网管、楼宇运维  |
| **C 端** | 一个产品（一个 Git 仓库） | 终端用户（会话 + 权限隔离） | SaaS 产品的 AI 助手 |

同一套 BuildingOS 部署可同时服务多个租户（多仓库）；一个租户内部可以是 B 端员工或 C 端用户集合——**租户与用户是正交的两个维度**。

## 4. 世界知识文档（World Knowledge，D19）

仓库 = 大脑 + 世界模型。世界知识文档由 harness 生成（老项目向导的"自动梳理"、生产伴生的诊断），**人评审后进库、版本化**——与代码一个待遇。

### toB：租户仓库

```
<tenant-repo>/
├── .buildingos/          # 大脑：行为文档（rules/skills/prompts/configs）
└── knowledge/            # 世界模型（t1 已定）
    ├── network.md        # harness 梳理：拓扑/设备/基线/操作规程
    ├── topology.yaml
    └── ...
```

### toC：产品仓库

```
<product-repo>/
├── .buildingos/          # 产品大脑（共享）
└── users/<user-id>/      # 该用户的世界知识（t2 已定）
    └── network.md
```

- **量级降级（t2 已定）**：用户知识优先进 Git（`users/<uid>/`）；用户量级过大（百万级）时降级到存储层（状态库 / 对象存储按需加载）——知识值得评审就尽量留 Git，工程上留退路。
- **自由格式（t3 已定）**：世界知识文档 M0 先自由 Markdown，不建 schema；等 M1 验证后再定轻量 frontmatter（id / type / source / 评审状态）。
- **引用**：技能用 `data:` 声明引用知识文档（如 `data: [knowledge/topology.yaml]`），CI 校验路径存在（D5）。

## 5. 技能层级（多套 skill 从哪来）

| 来源                          | 例子             | 覆盖规则       |
| --------------------------- | -------------- | ---------- |
| 平台内置包                       | UI 技能、系统技能     | 默认层        |
| 行业模板包（M4）                   | IoT 运维模板、医疗模板  | 可被租户覆盖     |
| 租户自有（`.buildingos/skills/`） | 客户自己的 know-how | 最近者胜（就近覆盖） |

- 同名技能优先级：**租户自有 > 行业模板 > 平台内置**（DSH 分层注册表现成模型；Codex 支持 project / user / plugin 技能）。
- **上传已有技能**：✅ 导入宽容（DSH / Codex 原生格式直接收，自动转 canonical 目录束，见 skill.schema §5）。
- **编辑**：✅ 文档即代码——改 → PR → 评审 → 合并 → 热加载；M3 admin 界面支持浏览 / 开 PR。
- **多产品 = 多租户仓库**，天然隔离。
- 【待 M5】同租户内按角色 / 用户分技能集合（`applies-to` 领地）。

## 6. 工具治理（MCP 四态，详见 api-contract §4.6）

| 动作     | 机制                                                                          | 状态       |
| ------ | --------------------------------------------------------------------------- | -------- |
| **使用** | 引擎 MCP 客户端，运行时调用                                                            | ✅ 天然     |
| **选择** | 模型自主，范围 = 已注册 ∩ 权限允许（rules 派生）                                              | ✅        |
| **指定** | skill `dependencies.tools[]` 引用（注册仍在 runtime.yaml，D3 分层）                    | ✅        |
| **安装** | AI 提议 → runtime.yaml 变更 PR → 评审合并 → 热加载（D14 延伸：新工具 = 新权限面）；运行时直装 M0 / M1 不做 | ⚠️ 受治理形态 |
