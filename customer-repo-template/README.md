# 客户配置仓库模板 —— `netops-customer-<slug>`

> 一客户一仓（私有）。一体机通过**只读 deploy key** 拉取，所有变更走 **PR**。
> 本模板用真实案例（home-01）填充，可直接对照改造。

## 仓里放什么

| 目录 | 内容 | 谁改 |
|---|---|---|
| `site.yml` | 站点、楼层、网段、VLAN、关键联系人 | 实施工程师 |
| `inventory/` | 设备台账（非密）+ 凭据**引用名** | 探针自动写 + 人工确认 |
| `topology/` | 期望拓扑：链路、归属、位置坐标（3D 布局来源） | 人工拖拽产生 |
| `policies/` | 扫描授权范围、变更策略、变更窗口 | 客户签字后录入 |
| `runbooks/` | 本客户设备的操作手册（可继承组织级公共库） | 领域专家策展 |
| `reports/` | 日报/周报/RCA 归档 | 系统自动提交 |

## 仓里绝不放什么

- ❌ 任何明文密码、密钥、Token
- ❌ 抓包原文（含隐私流量）
- ❌ 客户个人信息、人脸/车牌截图
- ❌ 摄像头视频片段

> 凭据只以 `VAULT://...` 引用名出现（见 `inventory/credential-refs.yml`）。
> CI 校验：任何文件不得命中明文凭据正则，否则 PR 直接失败。
> 若客户强制要求密码入库，启用 SOPS + age（见 `.sops.yaml.example`），但**默认方案是引用名 + 本地 Vault**。

## 变更流程

```
产品 UI 上的修正/变更
  → 本地分支 + PR（自动附：影响面、回滚方案、证据链接）
    → Reviewer 审批
      → 合并
        → 一体机 webhook/轮询拉取 → 热加载 → 探针复测 → 结果回写 PR 评论
```

## 分支与标签约定

- `main`：客户当前生效状态（受保护，只接受 PR）
- `probe/auto`：探针自动提交的台账更新分支
- `report/yyyy-mm-dd`：报告归档分支
- 标签 `baseline/yyyy-mm-dd`：基线快照，用于"相对基线"的漂移对比
