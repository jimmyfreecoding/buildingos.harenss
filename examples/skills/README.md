This directory holds example BuildingOS know-how documents and doubles as the **acceptance case** for the [skill schema](../../schemas/skill.schema.md) (M0-settled items): it verifies that the schema is easy to write, easy to read, and compiles into both engines' views.

## The three-view compile demo

### Unified format (tenant repository) — this example's SKILL.md itself

### → Codex view (`.codex/skills/network-diagnose/`)

```markdown
---
name: network-diagnose
description: 基于网络遥测诊断交换机/AP 健康度，输出带置信度的结构化结论
metadata:
  short-description: 网络健康诊断
---
```

```yaml
# openai.yaml (companion, generated by compile)
interface:
  display_name: 网络诊断
  short_description: 快速定位网络故障
  brand_color: '#2563EB'
  default_prompt: 帮我诊断一下网络问题
policy:
  allow_implicit_invocation: false
dependencies:
  tools:
    - type: mcp
      value: telemetry
      transport: stdio        # derived from runtime.yaml (Q3: the skill writes references only)
```

`references/thresholds.md` stays as-is under the `references/` subdirectory.

### → DSH view (`.dsh/skills/network-diagnose/SKILL.md`)

```markdown
---
name: network-diagnose
description: 基于网络遥测诊断交换机/AP 健康度，输出带置信度的结构化结论
whenToUse: 用户报告延迟升高、丢包、端口抖动、设备离线时
metadata:
  short-description: 网络健康诊断
  author: ops-team
  version: 1.0.0
  x-buildingos:               # lossless carry (decisions Q1/Q2; DSH runtime-ignores)
    ui:
      display-name: 网络诊断
      short-description: 快速定位网络故障
      brand-color: '#2563EB'
      default-prompt: 帮我诊断一下网络问题
    invocation-implicit: false
---
```

`resourceBase` points to the `references/` directory; referenced resources load on demand, no directory enumeration.

## Dependency resolution demo (Q3 layering)

This example references `telemetry`. The tenant-level registration lives in [examples/configs/runtime.yaml](../configs/runtime.yaml) (configs.schema draft exists):

```yaml
# examples/configs/runtime.yaml (excerpt)
mcp_servers:
  - name: telemetry
    transport: stdio
    command: npx telemetry-mcp
```

CI rule: a skill's `dependencies.tools[].value` must resolve in `runtime.yaml`, or the PR fails.

## Acceptance findings (learned while writing the example)

1. The schema has enough fields for real content, with nothing missing; the `ui:` block gives skills "a name and a face" and is a ready data source for the M3 dynamic UI.
2. The body conventions (steps / confidence / read-only default / authorization boundary) align naturally with the example content — "honest output" and "governance" are not decoration; they are the writing standards for skill bodies.
3. The "tenant data dependency" question surfaced by this example is settled (M0 decision record item 5): a new `data:` field, distinct from `references:` (references = skill resources; data = tenant data files). This example's frontmatter follows it.
